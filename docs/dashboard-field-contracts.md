## Purpose

This document defines the customer-facing data contract for each primary Wealth Factory screen.

For every page, it answers:

- what the page is for
- what data may be exposed directly
- what backend state must be translated into customer-safe language
- what must be hidden completely
- what the main CTA and user decisions should be

This is a UI boundary document. It should prevent the dashboard from drifting into a Paperclip admin surface.

## Global Rules

Across all customer pages:

- Never expose `Paperclip`, prompts, raw skill-pack names, commands, agents, tool calls, long raw logs, queue internals, Docker/container language, backend secret handles, provider secrets, or service-role mechanics.
- Customer-facing IDs must be Wealth Factory IDs only.
- Workflow and result language must stay business-safe and outcome-oriented.
- Provider and storage connections may show status and action-needed states, but never raw OAuth or secret material.
- Statuses should use customer-safe vocabulary such as `Ready`, `In progress`, `Needs approval`, `Needs connection`, `Delayed`, and `Failed`.

## Page Contract Template

Each page below is organized as:

- Purpose
- Directly exposed fields
- Translated fields
- Hidden fields
- Primary decisions / actions
- Risks to avoid

## Home

### Purpose

Give the user a clean operational overview of what matters today.

### Directly Exposed Fields

- Current focus title
- Current focus summary
- Due-today or urgency chips
- Top priority items
- Safe business metrics such as:
  - campaigns in motion
  - deliverables due
  - upcoming deadlines
  - package-safe KPI summaries
- Work queue item titles
- Schedule item titles and times
- Expiring download summaries

### Translated Fields

- internal workflow state -> `In progress`, `Ready`, `Delayed`, `Needs approval`
- retry behavior -> `Still processing` or `Delayed`
- connection refresh issue -> `Needs connection`
- outbox or queue delay -> `Delayed`
- supportable export problem -> `Export failed` or `Reconnect storage`

### Hidden Fields

- raw queue state
- retry counts
- worker claim state
- internal run graph
- Paperclip workflow identifiers
- backend log payloads

### Primary Decisions / Actions

- open the highest-priority task
- approve an item
- continue a workflow
- review a result
- reconnect a provider or storage destination

### Risks To Avoid

- making Home too dense
- duplicating the same task in hero, right rail, and work queue
- showing platform-health language instead of business-action language

## Workflows

### Purpose

Show the approved workflows available inside the tenant's package boundary.

### Directly Exposed Fields

- workflow ID generated by Wealth Factory
- workflow name
- workflow description
- package name
- employee association, if customer-safe
- required provider labels
- last updated timestamp

### Translated Fields

- availability state -> `Available`, `Needs connection`, `Needs add-on`
- provider capability checks -> `OpenAI required`, `Storage optional`, `Connection needed`
- internal employee gating -> `Needs add-on`
- cooldown or transient delay -> `Try again in a moment`

### Hidden Fields

- Paperclip workflow ID
- prompt bundle name
- skill/command mapping
- private asset references
- raw entitlement engine output

### Primary Decisions / Actions

- launch workflow
- review workflow details
- see required connections

### Risks To Avoid

- turning this page into a technical registry
- showing workflows that are not actually runnable in the tenant's installed package or purchased add-ons
- leaking provider internals instead of simple readiness
- turning `Workflows` into an upsell or discovery surface; discovery belongs in the `Skills` marketplace lane

## Results

### Purpose

Show completed and in-progress outcomes, including run history, approvals, and exports.

### Directly Exposed Fields

- result ID generated by Wealth Factory
- related workflow name
- sanitized result summary
- created and updated timestamps
- related file summaries

### Translated Fields

- run state -> `Queued`, `In progress`, `Completed`, `Failed`, `Needs approval`
- approval state -> `Awaiting review`, `Approved`, `Revision needed`
- export/download state -> `Ready to download`, `Sent to Google Drive`, `Sent to Dropbox`, `Expires in 24 hours`
- internal exception -> safe error codes such as `service_unavailable`, `tenant_paused`, `connection_required`
- artifact transfer state -> `Sent to Google Drive`, `Sent to Dropbox`, `Expires in 24 hours`

### Hidden Fields

- raw run logs
- tool traces
- internal request bodies
- provider response payloads
- queue retry mechanics
- private correlation graphs

### Primary Decisions / Actions

- review result
- approve or reject
- download output
- export to customer-owned storage
- open support flow if result failed

### Risks To Avoid

- making run history look like an ops console
- exposing too much intermediate state
- showing raw failure detail that belongs only to operators

## Providers

### Purpose

Manage BYOK providers, subscriptions, and storage connectivity in a customer-safe way.

### Directly Exposed Fields

- connection ID generated by Wealth Factory
- provider label
- storage label
- last updated timestamp
- allowed non-secret metadata such as OpenAI project ID

### Translated Fields

- provider/storage state -> `Connected`, `Missing`, `Expired`, `Needs attention`
- auth refresh failure -> `Reconnect required`
- permission mismatch -> `Needs attention`
- provider not installed for package -> `Not needed for your package`
- storage export blocked -> `Connect storage to continue`

### Hidden Fields

- API keys
- OAuth access tokens
- refresh tokens
- raw secret references
- vault paths
- private provider file IDs

### Primary Decisions / Actions

- connect provider
- connect Google Drive
- connect Dropbox
- choose which approved provider powers a supported workflow family
- rotate or revoke a connection
- resolve a connection issue

### Risks To Avoid

- exposing secret-adjacent implementation details
- making every provider global when some are package-specific
- turning key and provider setup into a scary infra page

## Package

### Purpose

Show the installed business system and its boundaries.

### Directly Exposed Fields

- package ID generated by Wealth Factory
- package name
- industry/category
- package type
- included workflows count
- included base roles
- allowed asset-group labels
- specialist add-ons available

### Translated Fields

- install state -> `Installed`, `Available`, `Not installed`
- subscription state -> `Active`, `Renewal due`, `Payment issue`
- entitlement state -> `Included`, `Requires add-on`, `Not in your package`
- package compatibility -> `Available for your business`
- package setup requirement -> `Connection needed to unlock this workflow`

### Hidden Fields

- private package asset IDs
- prompt/rule bundle names
- Paperclip mappings
- internal asset version tables

### Primary Decisions / Actions

- review package scope
- see what is included
- see what needs to be connected
- discover compatible add-ons

### Risks To Avoid

- letting the page read like a billing SKU list only
- leaking technical package implementation
- confusing installed system scope with Marketplace browsing

## Team

### Purpose

Present the tenant's currently available built-in employees, hired roles, and marketplace expansion lane.

### Directly Exposed Fields

- team/employee ID generated by Wealth Factory
- display name
- mini resume / role summary
- outcome summary
- package compatibility
- connection requirements
- pricing or included label
- marketplace availability summary

### Translated Fields

- team access state -> `Active`, `Included`, `Available as add-on`, `Needs connection`
- hidden capability set -> public summary of what the employee or hire can do
- gated entitlement -> `Available with your package`, `Hire to unlock`, `Requires connection`

### Hidden Fields

- raw skill-pack names
- prompt bundles
- hidden internal command sets
- backend capability registry details

### Primary Decisions / Actions

- review employee details
- see if a role is active
- browse the marketplace lane
- view unlocked power plays
- hire or activate an add-on
- connect required providers

### Risks To Avoid

- making employees and hires sound like literal HR staff
- exposing internals instead of outcomes
- allowing the marketplace lane to imply cross-package capability

## Insights

### Purpose

Show customer-safe usage, outcome, and performance summaries.

### Directly Exposed Fields

- time-window label
- workflow completion counts
- output volume summaries
- package KPI summaries
- safe spend or usage summary, if intentionally productized

### Translated Fields

- token/provider usage -> customer-safe usage summary
- latency or turnaround data -> `Average turnaround`
- internal reliability summary -> `On-time rate`, `Completed successfully`

### Hidden Fields

- raw token accounting tables
- trace spans
- retry counts
- queue metrics
- internal observability schemas

### Primary Decisions / Actions

- review performance trends
- change time window
- compare business output periods

### Risks To Avoid

- turning Insights into operator telemetry
- exposing low-level provider accounting without product meaning
- crowding the page with charts that do not support decisions

## Profiles

### Purpose

Let the user switch between owned company contexts or operating profiles within the same allowed package family.

### Directly Exposed Fields

- profile ID generated by Wealth Factory
- company/profile name
- package family label
- last activity summary
- owner/contact summary

### Translated Fields

- profile state -> `Active`, `Available`, `Needs attention`
- package-family restriction -> `Available in this package family`
- profile setup issue -> `Needs connection`, `Needs owner review`

### Hidden Fields

- cross-tenant identifiers
- operator impersonation state
- internal organization mappings
- backend ownership joins

### Primary Decisions / Actions

- switch active profile
- review company context
- create a new approved profile within the package family
- resolve a setup issue

### Risks To Avoid

- making profile switching feel like admin impersonation
- exposing cross-tenant relationships
- suggesting the user can cross package-family boundaries without entitlement

## Files

### Purpose

Let the user work with temporary outputs and move important files into customer-owned storage.

### Directly Exposed Fields

- file/artifact ID generated by Wealth Factory
- related workflow/result name
- file type
- file title
- expiration time

### Translated Fields

- file state -> `Ready`, `Processing`, `Needs attention`
- download/export state -> `Ready to download`, `Sent to Google Drive`, `Sent to Dropbox`, `Export failed`
- export destination status -> `Saved to Google Drive`, `Saved to Dropbox`, `Reconnect storage`
- temporary retention state -> `Expires in 24 hours`
- export success -> `Sent to Google Drive` or `Sent to Dropbox`
- failed export -> `Export failed` or `Reconnect storage`

### Hidden Fields

- raw artifact storage paths
- temp server paths
- provider file IDs unless surfaced through a later safe alias
- internal cleanup job state

### Primary Decisions / Actions

- download file
- send to Google Drive
- send to Dropbox
- check export failure

### Risks To Avoid

- making WF look like permanent storage
- hiding expiry too much
- exposing backend storage internals

## Assistant

### Purpose

Provide bounded, package-grounded help and support intake.

### Directly Exposed Fields

- installed package context
- approved workflow summaries
- current result summaries
- connection state summaries
- support-case input fields

### Translated Fields

- backend state explanations -> customer-safe guidance such as `Your assistant is getting ready`, `Connection needed`, `Try again in a moment`
- support routing -> `Open a support request`, `Reconnect storage`, `Review this result`

### Hidden Fields

- unrestricted chat capability
- off-topic world knowledge mode
- backend diagnostics
- Paperclip internals
- tool traces
- secret or operator-only state

### Primary Decisions / Actions

- ask a package-safe question
- get routed to a workflow
- understand a result
- open support intake mode

### Risks To Avoid

- letting Assistant become a generic chatbot
- allowing it to invent workflows outside package bounds
- turning support intake into hidden infrastructure diagnostics

## Billing

### Purpose

Show subscription and charge information in a customer-safe, account-health-focused way.

### Directly Exposed Fields

- billing profile ID generated by Wealth Factory
- current plan name
- renewal date
- invoice or charge summaries
- add-on specialist charges

### Translated Fields

- billing state -> `Active`, `Renewal due`, `Payment issue`, `Past due`
- package billing relationship -> `Included in your plan`, `Billed separately`, `Requires upgrade`

### Hidden Fields

- payment processor internal IDs
- margin/cost internals
- risk or fraud flags
- backend billing event payloads

### Primary Decisions / Actions

- review account health
- update billing method
- resolve payment issue
- review renewal timing

### Risks To Avoid

- mixing billing with package entitlements in confusing ways
- showing charge states without clear action guidance
- leaking payment-provider internals

## Settings

### Purpose

Manage customer-safe account preferences, team access, notifications, support links, and tenant-visible audit history.

### Directly Exposed Fields

- account display name
- user display name or email
- tenant role
- notification preferences
- support links
- tenant-visible audit event summaries
- team member summaries
- theme preset selection

### Translated Fields

- access state -> `Owner`, `Member`
- audit event types -> customer-safe event labels such as `Connection updated`, `Hire added`, `Export completed`
- team access restrictions -> `Owner approval required`
- theme state -> `Foundry`, `Midnight`, `Ledger`, `Ember`

### Hidden Fields

- operator-only roles
- internal admin assignments
- raw audit payloads
- secret lifecycle internals
- backend authorization traces

### Primary Decisions / Actions

- update preferences
- manage team access within allowed role boundaries
- review tenant-visible audit history
- choose dashboard theme
- open support resources

### Risks To Avoid

- letting Settings become an operator/admin dumping ground
- exposing audit rows that contain backend or secret-adjacent details
- confusing customer role management with internal operator access

## Implementation Note

These field contracts should drive:

- DTO design
- page layout design
- response-guard tests
- Playwright assertions
- support copy

If a field does not clearly belong in `Directly Exposed Fields` or `Translated Fields`, it should not reach the customer UI.
