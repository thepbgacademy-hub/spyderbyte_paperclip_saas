First Subscriber Entry URL Blocker

Documented and corrected the handoff path that sent the stand-in subscriber to a dead apex /board route.

What Failed

The stand-in used https://spyderbyte.cloud/board?workflowId=wf_connect_first_workflow and received HTTP 404. The www board path also finalized to the invalid apex route.

Correction

The first-subscriber board entry is now pinned to https://wf-api.spyderbyte.cloud/board?workflowId=wf_connect_first_workflow. That path is intentionally auth-gated.

Guardrails

No VPS, Docker, Caddy, DNS, database, runtime, worker, scheduler, export, onboarding UI, workflow/package, rollback, or cutover mutation was performed.

Browser Harness

The sandbox Chrome flow reached the authenticated Wealth Factory board. The next visible blocker is provider execution: the live lane returned HTTP 401 and must be corrected through the OpenAI device/Codex subscription binding, not a BYOK API-key assumption.
